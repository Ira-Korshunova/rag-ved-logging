# RAG-ассистент по ВЭД + логирование (ДЗ «Портфолио: метрики и логирование»)

Готовый RAG-ассистент по внешнеэкономической деятельности (ВЭД): таможня, Incoterms,
ТН ВЭД, формы международных расчётов, валютный контроль. Подключён к OpenAI-совместимому
API **Alibaba DashScope (Qwen)** — `qwen3.7-max` для генерации + `text-embedding-v3` для
эмбеддингов, по одному ключу.

**ДЗ мод 8.9 (урок PEcf09):** в проект внедрено логирование каждого запроса по конвейеру
урока (5 событий), статистика из логов, правила безопасности (анонимность, доступ,
срок хранения). Проект развёрнут на сервере: веб-интерфейс (`webapp.py`) + gunicorn.

## Архитектура

```
пользователь
    │  вопрос
    ▼
┌─────────────── app.py (консольный интерфейс) ───────────────┐
│                            ▼                                  │
│   RAGPipeline (rag_pipeline.py)                              │
│      1. проверка кеша (SQLite, cache.py)                      │
│      2. поиск по векторам (vector_store.py, ChromaDB)         │
│      3. формирование промпта с контекстом                     │
│      4. генерация ответа через LLM (qwen3.7-max, DashScope)   │
│      5. сохранение ответа в кеш                                │
└──────────────────────────────────────────────────────────────┘
```

- **Векторное хранилище:** ChromaDB (косинусное расстояние, персистентное).
- **Эмбеддинги:** `text-embedding-v3` через DashScope.
- **Генерация:** `qwen3.7-max` через DashScope.
- **Кеш:** SQLite, ключ = SHA256(вопрос) → ответ + контекст.
- **Оценка:** RAGAS (faithfulness, context precision) — опционально.

## Логирование по конвейеру урока (метрики и логирование)

**Проблема.** Без логов RAG-ассистент — чёрный ящик: непонятно, сколько запросов приходит,
сколько отклоняется и почему, какая доля ответов обслуживается кешем, сколько стоит
(в токенах) один ответ и где ломается пайплайн. Логи превращают это в измеримые числа.

**Что логируем — конвейер из 5 событий урока на каждый запрос:**

| # | Событие | Что фиксируется |
|---|---|---|
| 1 | `request_received` | пользователь отправил запрос (текст после PII-маскирования) |
| 2 | `request_accepted` / `request_rejected` | отклонение — **с причиной**: `empty_query`, `too_long_query` |
| 3 | `processing_started` | ассистент приступил к выполнению |
| 4 | `answer_prepared` | модель, prompt/completion токены, длительность, из кеша или нет |
| 5 | `answer_sent` | система отправила ответ (или ошибка обработки с её текстом) |

**Где хранится:** SQLite (`request_logs.db`, таблица `request_log` с индексами) +
JSONL-файл (`request_logs.jsonl`, строка на событие — для выгрузки в аналитику).
Модуль: `logging_pipeline.py` (класс `RequestLogger`), врезан в `RAGPipeline.query()`.

**Пример записи (JSONL):**

```json
{"request_id": "a1b2c3d4e5f6", "event": "answer_prepared", "reason": null,
 "model": "qwen3.7-max", "prompt_tokens": 812, "completion_tokens": 210,
 "duration_ms": 1830, "from_cache": false, "error": null,
 "query_masked": "Позвоните по [телефон] насчёт аккредитива", "created_at": "2026-09-19T22:41:03"}
```

**Статистика из логов** (`RequestLogger.get_stats(period_days)`): запросов за период,
принято/отклонено с разбивкой по причинам, доля кеша, средняя длительность, токены
по моделям, ошибки. Где смотреть:
- консоль: команда `stats` в `app.py` (секция «Логи запросов»);
- веб: страница `/stats?key=ПАРОЛЬ` (пароль в `STATS_PASSWORD`).

**Безопасность (таблица урока):**

| Аспект | Правило урока | Реализация |
|---|---|---|
| Анонимность | не хранить ФИО, телефоны и т.п. | PII-фильтр `mask_pii()` до записи: телефоны → `[телефон]`, email → `[email]`, карты → `[карта]`, паспорта → `[документ]` |
| Шифрование | данные в защищённом виде | ключи только в `.env` (вне репозитория), БД и JSONL вне репозитория (`.gitignore`) |
| Доступ | разграничение для сотрудников | статистика по паролю (`STATS_PASSWORD`); логи — только на сервере |
| Срок хранения | зависит от политики | ретеншн `LOG_RETENTION_DAYS` (по умолчанию 90 дней), очистка при старте |

**Тесты:** `tests/test_logging_pipeline.py` — 17 тестов (конвейер, причины отказов,
PII-маскирование, ретеншн, статистика, JSONL): `pytest tests/ -q`.

## База знаний (data/)

ВЭД-документы, по которым отвечать ассистент:

| Файл | Содержание |
|------|------------|
| `incoterms_2020.txt` | Базисы поставки Incoterms 2020 |
| `tn_ved_structure.txt` | Структура ТН ВЭД |
| `customs_procedures.txt` | Таможенные процедуры ЕАЭС (ИМ40, ЭК20, транзит, СВХ…) |
| `ved_payments.txt` | Формы международных расчётов (аванс, аккредитив, инкассо, открытый счёт) |
| `fz_173_currency.txt` | Валютный контроль по ФЗ-173 |
| `Список_документов_для_ВЭД.md` | Перечень документов для ВЭД-сделки |
| `ved_case_example.txt` | Кейс: импорт из Китая шаг за шагом |
| `ved_faq.txt` | Частые вопросы по ВЭД |
| `logistics_dictionary.txt` | Логистический глоссарий |
| `словарь_МТ.txt` | Словарь международных терминов |

Все `.txt`/`.md` из папки `data/` индексируются автоматически при первом запуске
(см. `vector_store.load_documents_from_folder`).

## Установка

Нужен Python 3.10+.

```bash
cd 5-8-final
pip install -r requirements.txt
```

## Настройка (.env)

Файл `.env` лежит в корне `5-8-final/` и уже заполнен рабочим ключом DashScope:

```dotenv
OPENAI_API_KEY=sk-ws-...        # ключ DashScope (Qwen)
OPENAI_BASE_URL=https://dashscope-intl.aliyuncs.com/compatible-mode/v1
MODEL_NAME=qwen3.7-max           # генеративная модель
EMBEDDING_MODEL=text-embedding-v3
TOP_K=7                         # сколько документов в контекст
```

> Ключ один и тот же работает и для генерации, и для эмбеддингов.
> Модель `qwen3-max` на этом ключе отдаёт 403 — поэтому стоит `qwen3.7-max`
> (из списка `qwen3-max / qwen3.7-max / qwen3.6-plus / qwen3.6-flash`).

## Запуск

**Консоль (локально):**

```bash
cd rag-ved-logging/assistant_api
python app.py
```

**Веб-интерфейс (для сервера):**

```bash
cd rag-ved-logging/assistant_api
python webapp.py                 # локально: http://127.0.0.1:8002
# на сервере:
gunicorn -w 1 -b 127.0.0.1:8002 webapp:app
```

Страница `/` — форма вопроса; `/stats?key=ПАРОЛЬ` — статистика логов (пароль
из `STATS_PASSWORD` в `.env`).

Внутри консоли:
- вводи вопросы по ВЭД;
- `stats` — статистика (кол-во чанков, размер кеша, модель, **логи запросов за неделю**);
- `clear` — очистить кеш;
- `exit` / `quit` — выход.

Примеры вопросов:
- «Что такое аккредитив во внешней торговле?»
- «Чем отличается CIF от FOB по Incoterms 2020?»
- «Что такое таможенная процедура ИМ40?»
- «Какие документы нужны для импорта?»
- «Что такое УНК и когда контракт ставится на учёт?»

## Оценка качества (опционально, RAGAS)

```bash
cd 5-8-final/assistant_api
python evaluate_ragas.py
```

Считает faithfulness и context precision на 5 ВЭД-вопросах. LLM-судья и эмбеддинги
RAGAS тоже идут через DashScope (`MODEL_NAME` / `EMBEDDING_MODEL` / `OPENAI_BASE_URL`).

## Структура

```
rag-ved-logging/
├── .env                    # ключи и модели (вне репозитория)
├── .gitignore
├── .dockerignore

├── requirements.txt
├── deploy/
│   ├── .env.server.example # шаблон .env для сервера (ключи вписывает Ирина)
│   └── DEPLOY_RAG.md       # пошаговый деплой на VPS: rsync → .env → docker + Traefik
└── assistant_api/
    ├── app.py              # консольный интерфейс
    ├── webapp.py           # веб-интерфейс для сервера (Flask + gunicorn)
    ├── rag_pipeline.py     # основной RAG-конвейер + врезка логирования
    ├── logging_pipeline.py # логирование: 5 событий урока, PII, ретеншн, статистика
    ├── vector_store.py     # ChromaDB + эмбеддинги + индексация папки
    ├── cache.py            # SQLite-кеш
    ├── evaluate_ragas.py   # оценка RAGAS
    ├── tests/
    │   └── test_logging_pipeline.py  # 17 тестов модуля логирования

```

**Деплой на сервер** — `deploy/DEPLOY_RAG.md`: контейнер в сети Traefik-стека,
субдомен `rag.cygnusweb.ru`, все хранилища (вектора, кеш, логи) в одном Docker-томе
`/app/state` (пути через `CHROMA_PATH` / `CACHE_DB_PATH` / `LOG_DB_PATH`).
