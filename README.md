# RAG-ассистент по ВЭД + логирование (ДЗ «Портфолио: метрики и логирование»)

Готовый RAG-ассистент по внешнеэкономической деятельности (ВЭД): таможня, Incoterms,
ТН ВЭД, формы международных расчётов, валютный контроль. Генерация — **DeepSeek**
(`deepseek-chat`) по OpenAI-совместимому API; эмбеддинги считаются **локально** на открытой
модели `intfloat/multilingual-e5-small` (MIT, 118 млн параметров — ~470 МБ весов, ~0,5 ГБ
в RAM, 384 измерения) — без внешних API и квот на этапе поиска.

**Развёрнут и работает:** https://ask.cygnusweb.ru — веб-интерфейс (Flask + gunicorn
в Docker за Traefik), те же логи пишут консольный режим и телеграм-бот.

**Родственные проекты:** ядро RAG-движка по ВЭД выходило раньше в
[porta-rag-mcp](https://github.com/Ira-Korshunova/porta-rag-mcp) (база знаний как
MCP-tools); этот кейс — отдельный урок про эксплуатацию: метрики, логи, кеш, веб.

## Архитектура

```
пользователь
    │  вопрос (веб / консоль / телеграм)
    ▼
┌──────────────── RAGPipeline (rag_pipeline.py) ─────────────────┐
│    1. проверка кеша (SQLite, cache.py)                          │
│    2. поиск по векторам (vector_store.py, ChromaDB)             │
│    3. формирование промпта с контекстом                         │
│    4. генерация ответа через LLM (deepseek-chat, DeepSeek API)  │
│    5. сохранение ответа в кеш                                   │
└─────────────────────────────────────────────────────────────────┘
    │        каждый шаг вписан в лог конвейера (logging_pipeline.py)
    ▼
SQLite request_logs.db + JSONL-файл   →   статистика (get_stats)
```

- **Векторное хранилище:** ChromaDB (косинусное расстояние, персистентное).
- **Эмбеддинги:** локальные `intfloat/multilingual-e5-small` через sentence-transformers
  (режим `EMBEDDING_PROVIDER=local`); e5 требует служебных префиксов `query:` /
  `passage:` — их добавляет код, пользователь их не видит. Доступен и API-режим.
- **Генерация:** `deepseek-chat` через DeepSeek API (`LLM_API_KEY`, `LLM_BASE_URL`).
- **Кеш:** SQLite, ключ = SHA256(вопрос) → ответ + контекст.

## Выбор эмбеддинг-модели (бенчмарк)

`evals/retrieval_benchmark.py` — 26 эталонных вопросов по ВЭД, метрика hit@5:

| Модель | hit@5 | RAM | Задержка эмбеддинга запроса |
|---|---|---|---|
| BAAI/bge-m3 | 92% | ~2,3 ГБ | — |
| **intfloat/multilingual-e5-small** | **92%** | **~0,5 ГБ** | **~8 мс (CPU)** |
| paraphrase-multilingual-MiniLM-L12-v2 | 77% | ~0,5 ГБ | — |

BGE-M3 по точности не лучше — и превысила доступный объём памяти сервера (2 ГБ RAM),
MiniLM заметно хуже. Итог: e5-small. На этапе поиска тексты запросов не покидают
сервер; наружу текст запроса уходит только при генерации ответа — в LLM (DeepSeek).

## Логирование по конвейеру урока (метрики и логирование)

**Проблема.** Без логов RAG-ассистент — чёрный ящик: непонятно, сколько запросов приходит,
сколько отклоняется и почему, какая доля ответов обслуживается кешем, сколько стоит
один ответ (в токенах и деньгах) и где ломается пайплайн.

**Что логируем — конвейер из 5 событий урока на каждый запрос:**

| # | Событие | Что фиксируется |
|---|---|---|
| 1 | `request_received` | пользователь отправил запрос (текст после PII-маскирования) + источник (`source`: web / console / telegram — как в схеме урока) |
| 2 | `request_accepted` / `request_rejected` | отклонение — **с причиной**: `empty_query`, `too_long_query` |
| 3 | `processing_started` | ассистент приступил к выполнению |
| 4 | `answer_prepared` | модель, prompt/completion токены, длительность, из кеша или нет |
| 5 | `answer_sent` | система отправила ответ (или ошибка обработки с её текстом) |

**Где хранится:** SQLite (`request_logs.db`, таблица с индексами) + JSONL-файл
(`request_logs.jsonl`, строка на событие — для выгрузки в аналитику).
Модуль: `logging_pipeline.py` (класс `RequestLogger`), врезан в `RAGPipeline.query()`.

**Пример записи (JSONL):**

```json
{"request_id": "a1b2c3d4e5f6", "event": "answer_prepared", "reason": null,
 "model": "deepseek-chat", "prompt_tokens": 812, "completion_tokens": 210,
 "duration_ms": 1830, "from_cache": false, "error": null,
 "query_masked": "Позвоните по [телефон] насчёт аккредитива", "created_at": "2026-10-02T22:41:03"}
```

**Статистика из логов** (`RequestLogger.get_stats(period_days)`): запросов за период,
принято/отклонено с разбивкой по причинам, **разбивка по источникам** (web / console /
telegram), число уникальных пользователей Telegram, доля кеша, средняя длительность,
токены по моделям, ошибки, стоимость генерации за период в долларах. Где смотреть:

- веб: `/stats?key=ПАРОЛЬ` и **панель оператора `/admin`** (вход формой, session-cookie) —
  статистика + лента последних событий конвейера + пополнение базы;
- консоль: команда `stats` в `app.py`;
- бот: команда `/stats` (периоды: `/stats` — 7 дней, `/stats 1` — сутки, `/stats 30`).

**Каналы (как в уроке PEcf09 — бот поверх того же движка):**

| Канал | Интерфейс | source в логе | user_id |
|---|---|---|---|
| Веб | `webapp.py` (Flask) | `web` | нет (анонимно) |
| Консоль | `app.py` | `console` | нет |
| Telegram | `telegram_bot.py` (токен из `TELEGRAM_BOT_TOKEN`) | `telegram` | пишется, как в коде урока; username не пишем (анонимность по таблице урока) |

Полный `user_id` остаётся только на сервере (база логов и JSONL); в CSV-выгрузке `/logs`
поле не выгружается вовсе, в панели `/admin` маскируется до вида «774…91» — по обрезанному
идентификатору аккаунт не восстанавливается.

Все три канала пишут логи в одну базу `request_logs.db`. Бот запускается вторым
контейнером того же образа (см. `deploy/DEPLOY_RAG.md`).

**Защита публичного входа:** `/ask` ограничен rate limit'ом с одного IP —
не более 6 вопросов в минуту и 150 в день (`RATE_LIMIT_PER_MINUTE` /
`RATE_LIMIT_PER_DAY`) — защита ключа LLM от выжигания.

**Безопасность (таблица урока):**

| Аспект | Правило урока | Реализация |
|---|---|---|
| Анонимность | не хранить ФИО, телефоны и т.п. | PII-фильтр `mask_pii()` до записи в лог: телефоны → `[телефон]`, email → `[email]`, карты → `[карта]`, паспорта → `[документ]` |
| Шифрование | данные в защищённом виде | ключи только в `.env` на сервере (вне репозитория), БД и JSONL вне репозитория (`.gitignore`) |
| Доступ | разграничение для сотрудников | `/stats` и `/admin` по паролю (`STATS_PASSWORD`); админ-функции бота — по `ADMIN_USER_IDS` |
| Срок хранения | зависит от политики | ретеншн `LOG_RETENTION_DAYS` (по умолчанию 90 дней), очистка при старте |

**Тесты:** `assistant_api/tests/test_logging_pipeline.py` — 22 теста (конвейер, причины
отказов, источники, user_id, PII-маскирование, ретеншн, статистика, JSONL):
`pytest assistant_api/tests/ -q`.

## База знаний (data/)

ВЭД-документы, по которым отвечает ассистент:

| Файл | Содержание |
|------|------------|
| `incoterms_2020.txt` | Базисы поставки Incoterms 2020 |
| `tn_ved_structure.txt` | Структура ТН ВЭД |
| `customs_procedures.txt` | Таможенные процедуры ЕАЭС (ИМ40, ЭК20, транзит, СВХ…) |
| `ved_payments.txt` | Формы международных расчётов (аванс, аккредитив, инкассо, открытый счёт) |
| `fz_173_currency.txt` | Валютный контроль по ФЗ-173 |
| `Список_документов_для_ВЭД.md` | Перечень документов для ВЭД-сделки |
| `ved_case_example.txt` | Кейс: импорт из Китая шаг за шагом |
| `ved_faq.txt` | Частые вопросы по ВЭД |
| `logistics_dictionary.txt` | Логистический глоссарий |
| `словарь_МТ.txt` | Словарь международных терминов |
| `fz_289_customs.txt` | ФЗ-289 «О таможенном регулировании в РФ» (конспект) |
| `tk_eaes.txt` | Таможенный кодекс ЕАЭС (конспект) |
| `eec_decisions_key.txt` | Ключевые решения Евразийской экономической комиссии |

Все `.txt`/`.md` из папки `data/` индексируются автоматически при первом запуске
(см. `vector_store.load_documents_from_folder`); всего в базе ~200 чанков.

**Пополнение базы (без пересборки):** инкрементальная индексация
(`vector_store.add_documents_from_folder`) — добавляются только файлы, которых ещё нет
в коллекции (дедупликация по метаданным source = имени файла), существующие вектора
не пересоздаются. Три способа:

- **панель `/admin`** — форма «Пополнение базы»: загрузка локального `.txt`/`.md`
  (до 2 МБ) с индексацией и явным сообщением об успехе; дубли по имени блокируются,
  при сорвавшейся индексации файл удаляется;
- **бот** — кнопка «📥 Пополнить базу» (видит только оператор) или просто отправка файла
  в чат: бот сохраняет документ в базу и индексирует; оператор определяется по
  `ADMIN_USER_IDS` — не-оператор получает вежливый отказ и служебных команд в меню ≡ не видит;
- **консоль** — команда `ingest` (переиндексация новых файлов в `data/`).

## Настройка (.env)

Ключи никогда не публикуются: реальные значения вписываются в `.env` на самом сервере
(`/opt/rag-ved/deploy/.env`, права 600) по шаблону [`deploy/.env.server.example`](deploy/.env.server.example):

```dotenv
EMBEDDING_PROVIDER=local            # эмбеддинги локально, без ключей
EMBEDDING_MODEL=intfloat/multilingual-e5-small
EMBEDDING_QUERY_PREFIX=query:
EMBEDDING_DOCUMENT_PREFIX=passage:
LLM_API_KEY=ВСТАВЬ_КЛЮЧ_DEEPSEEK    # ключ вписывается только на сервере
LLM_BASE_URL=https://api.deepseek.com
MODEL_NAME=deepseek-chat
TOP_K=7                             # сколько документов в контекст
TELEGRAM_BOT_TOKEN=ВСТАВЬ_ТОКЕН_БОТА
ADMIN_USER_IDS=ВСТАВЬ_СВОЙ_TG_USER_ID
STATS_PASSWORD=ПРИДУМАЙ_ПАРОЛЬ      # доступ к /stats и /admin
LOG_RETENTION_DAYS=90
RATE_LIMIT_PER_MINUTE=6
RATE_LIMIT_PER_DAY=150
```

## Запуск

Нужен Python 3.10+; зависимости — `pip install -r requirements.txt`.

**Консоль (локально):**

```bash
cd assistant_api
python app.py
```

**Веб-интерфейс (локально):**

```bash
cd assistant_api
python webapp.py                   # http://127.0.0.1:8002
```

Страница `/` — форма вопроса с источниками под ответом и бейджем «из кеша»;
`/about` — как работает ассистент; `/stats?key=ПАРОЛЬ` — статистика логов;
`/admin` — панель оператора (статистика, лента событий, загрузка документов).

В консоли:
- вопросы по ВЭД вводятся обычным текстом;
- `stats` — статистика (кол-во чанков, размер кеша, модель, **логи запросов за неделю**);
- `clear` — очистить кеш;
- `ingest` — добавить в базу новые файлы из папки `data/`;
- `exit` / `quit` — выход.

Примеры вопросов:
- «Что такое аккредитив во внешней торговле?»
- «Чем отличается CIF от FOB по Incoterms 2020?»
- «Что такое таможенная процедура ИМ40?»
- «Какие документы нужны для импорта?»
- «Что такое УНК и когда контракт ставится на учёт?»

## Структура

```
rag-ved-logging/
├── Dockerfile              # контейнер для VPS (gunicorn, 1 воркер)
├── requirements.txt
├── deploy/
│   ├── .env.server.example # шаблон .env для сервера (ключи вписываются вручную)
│   ├── DEPLOY_RAG.md       # пошаговый деплой на VPS: rsync → .env → docker + Traefik
│   └── redeploy.sh         # обновление установленного проекта одной командой
└── assistant_api/
    ├── app.py              # консольный интерфейс
    ├── webapp.py           # веб-интерфейс (Flask + gunicorn): витрина, /about, /stats, /admin
    ├── telegram_bot.py     # телеграм-канал (source=telegram, как в уроке)
    ├── rag_pipeline.py     # основной RAG-конвейер + врезка логирования
    ├── logging_pipeline.py # логирование: 5 событий урока, PII, ретеншн, статистика
    ├── vector_store.py     # ChromaDB + эмбеддинги + инкрементальная индексация
    ├── cache.py            # SQLite-кеш
    ├── tests/
    │   └── test_logging_pipeline.py  # 22 теста модуля логирования
    └── data/               # ВЭД-документы (база знаний)
```

**Деплой на сервер** — `deploy/DEPLOY_RAG.md`: контейнер в сети Traefik-стека,
субдомен `ask.cygnusweb.ru`, все хранилища (вектора, кеш, логи, загруженные документы)
в одном Docker-томе `/app/state` (пути через `CHROMA_PATH` / `CACHE_DB_PATH` /
`LOG_DB_PATH` / `DATA_DIR`).

```bash
rm -rf assistant_api/chroma_db
rm -f assistant_api/api_rag_cache.db
python assistant_api/app.py       # сборка базы с нуля при первом запуске
```
