# Отчёт по домашнему заданию (модули 5–8)

**Тема:** Готовый RAG-ассистент по внешнеэкономической деятельности (ВЭД) с подключением к OpenAI-совместимому API (Alibaba DashScope / Qwen).

**Формулировка ДЗ:** «На базе предыдущих занятий и домашних заданий модуля необходимо создать готового RAG-ассистента, а также подключить его к OpenAI API или GigaChat (на твоё усмотрение). В ответном сообщении прикрепи ссылку на свой проект.»

---

## 1. Что сделано

Собран готовый RAG-ассистент по ВЭД — консольное приложение, запускаемое одной командой `python app.py`. Ассистент отвечает на вопросы по таможне, Incoterms, ТН ВЭД, формам международных расчётов и валютному контролю, опираясь на собственную базу знаний, и подключён к живой LLM через API.

Архитектура конвейера:
```
пользователь
    │  вопрос
    ▼
app.py (консольный интерфейс)
    ▼
RAGPipeline (rag_pipeline.py)
    1. проверка кеша (SQLite, cache.py)
    2. поиск по векторам (vector_store.py, ChromaDB)
    3. формирование промпта с контекстом
    4. генерация ответа через LLM (qwen3.7-max, DashScope)
    5. сохранение ответа в кеш
```

Компоненты:
- **Векторное хранилище:** ChromaDB, косинусное расстояние, персистентное (`chroma_db/`).
- **Эмбеддинги:** `text-embedding-v3` через DashScope.
- **Генерация:** `qwen3.7-max` через DashScope.
- **Кеш:** SQLite, ключ = SHA256(вопрос) → ответ + контекст (`api_rag_cache.db`).
- **Оценка:** RAGAS (faithfulness, context precision) — `evaluate_ragas.py`.
- **Цитирование:** каждый чанк несёт метаданные `source` (имя файла), ответ завершается строкой `[источник: …]`.

## 2. База знаний (data/)

Собственные ВЭД-документы, по которым отвечает ассистент (10 файлов, 165 чанков):

| Файл | Содержание |
|------|------------|
| `incoterms_2020.txt` | Базисы поставки Incoterms 2020 |
| `tn_ved_structure.txt` | Структура ТН ВЭД |
| `customs_procedures.txt` | Таможенные процедуры ЕАЭС (ИМ40, ЭК20, транзит, СВХ…) |
| `ved_payments.txt` | Формы международных расчётов (аванс, аккредитив, инкассо, открытый счёт) |
| `fz_173_currency.txt` | Валютный контроль по ФЗ-173 |
| `Список_документов_для_ВЭД.md` | Перечень документов для ВЭД-сделки |
| `ved_case_example.txt` | Кейс: импорт из Китая шаг за шагом |
| `ved_faq.txt` | Частые вопросы по ВЭД |
| `logistics_dictionary.txt` | Логистический глоссарий |
| `словарь_МТ.txt` | Словарь международных терминов |

Все `.txt`/`.md` из папки `data/` индексируются автоматически при первом запуске (`vector_store.load_documents_from_folder`).

## 3. Подключение к LLM API

Использован **Alibaba DashScope (Qwen)** — OpenAI-совместимый API. Один и тот же ключ работает и для генерации, и для эмбеддингов (это «две модели»: qwen3.7-max + text-embedding-v3, через единую точку входа).

`.env` (в корне `5-8-final/`):
```dotenv
OPENAI_API_KEY=sk-ws-...        # ключ DashScope (Qwen)
OPENAI_BASE_URL=https://dashscope-intl.aliyuncs.com/compatible-mode/v1
MODEL_NAME=qwen3.7-max           # генеративная модель
EMBEDDING_MODEL=text-embedding-v3
TOP_K=7                         # сколько документов в контекст
```

Почему `qwen3.7-max`: модель выбрана из списка `qwen3-max / qwen3.7-max / qwen3.6-plus / qwen3.6-flash`. На текущем ключе `qwen3-max` отдаёт 403, `text-embedding-v4/v2` — 400; рабочие и доступные — `qwen3.7-max` (флагманская, выбрана) и `text-embedding-v3`. Проверено прямыми запросами к API: `qwen3.7-max`, `qwen3.6-plus`, `qwen3.6-flash` → 200; `text-embedding-v3` → 200.

## 4. Запуск

```bash
cd 5-8-final
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd assistant_api
python app.py
```

При первом запуске ассистент индексирует все ВЭД-документы (по одному embedding-запросу на чанк) и сохранит векторное хранилище в `chroma_db/`. Дальше стартует мгновенно.

Команды в консоли: `stats` — статистика, `clear` — очистить кеш, `exit` — выход.

Оценка качества (опционально):
```bash
cd assistant_api
python evaluate_ragas.py
```
LLM-судья и эмбеддинги RAGAS тоже идут через DashScope (`MODEL_NAME` / `EMBEDDING_MODEL` / `OPENAI_BASE_URL`).

## 5. Чем 5-8 отличается от прошлых уроков (5_3 → 5_7)

5_3–5_7 — кирпичики по отдельности, 5_8 — собранный продукт:

| Урок | Что делали |
|------|-----------|
| 5_3 | Первый демо-RAG на ChromaDB — показать векторный поиск |
| 5_4 | Агент / рабочий бот |
| 5_5 | n8n — визуальная автоматизация |
| 5_6 | v2-наработка |
| 5_7 | Дополнения: оценка (RAGAS), масштабирование, оптимизация |
| **5_8** | **Готовый RAG-ассистент + подключение к реальному LLM API (OpenAI/GigaChat)** |

5_8 — это интеграция: один запуск `python app.py` и работает цельный конвейер кеш → поиск → генерация → кеш. Плюс требование «подключить к OpenAI API или GigaChat» — к живой модели, а не заглушке.

## 6. Чем `5-8-final` отличается от исходного шаблона урока (папка `prompt-5_8`)

Шаблон урока был заточен под OpenAI и учебные тексты про машинное обучение. Переписан под ВЭД и Qwen:

| Было в шаблоне | Стало в `5-8-final` |
|---|---|
| `model="gpt-4o-mini"` (хардкод) | `MODEL_NAME=qwen3.7-max` из `.env` |
| `text-embedding-3-small` (хардкод) | `EMBEDDING_MODEL=text-embedding-v3` из `.env` |
| Клиент OpenAI без `base_url` | `OPENAI_BASE_URL` → DashScope (OpenAI-совместимый эндпоинт) |
| `data/docs.txt` — один файл про ML/RAG | Папка `data/` из 10 ВЭД-документов |
| `load_documents(file)` — один файл | `load_documents_from_folder()` — все `.txt/.md` |
| Контекст без указания источника | Метаданные `source` + ссылки `[источник: …]` в ответе |
| `top_k=3` захардкожен | `TOP_K=7` из `.env` |
| RAGAS звал `gpt-4o` (нет в DashScope) | RAGAS-судья и эмбеддинги через DashScope/Qwen |
| Вопросы про «машинное обучение» | ВЭД-вопросы (аккредитив, Incoterms, ИМ40…) |

Ключевое архитектурное отличие: **один DashScope-ключ работает и для генерации, и для эмбеддингов** — две модели (qwen3.7-max + text-embedding-v3) через единую OpenAI-совместимую точку, тогда как шаблон подразумевал классический OpenAI.
